# BAB I  
## PENDAHULUAN

### 1.1 Latar Belakang

Basis data merupakan bagian penting dalam sebuah sistem informasi karena digunakan untuk menyimpan dan mengelola data secara terstruktur. Agar data yang tersimpan tetap konsisten dan sesuai dengan aturan yang telah ditentukan, database tidak hanya membutuhkan tabel, tetapi juga aturan yang dapat menjaga integritas data.

Pada praktikum Modul 5 dilakukan penerapan rancangan database Kopma ke dalam MariaDB menggunakan Data Definition Language (DDL). Struktur database yang sebelumnya telah dirancang melalui proses normalisasi dan ERD diterapkan menjadi tabel-tabel nyata pada database `kopma_039`.

Selain membuat tabel, praktikum ini juga menerapkan berbagai constraint, yaitu Primary Key, Foreign Key, UNIQUE, NOT NULL, DEFAULT, dan CHECK. Constraint digunakan agar database dapat menolak data yang tidak sesuai dengan aturan bisnis secara otomatis.

Pada praktikum ini juga dilakukan pengujian terhadap constraint dengan memasukkan data yang sengaja dibuat salah. Pengujian tersebut menghasilkan beberapa kode error, seperti `1062`, `1452`, dan `4025`. Hal tersebut membuktikan bahwa aturan yang diberikan pada struktur database dapat dijaga langsung oleh MariaDB.

# BAB II  
## DASAR TEORI

### 2.1 Data Definition Language

Data Definition Language atau DDL merupakan bagian dari SQL yang digunakan untuk membuat dan mengubah struktur database. Perintah DDL yang digunakan dalam praktikum antara lain:

- `CREATE DATABASE`
- `CREATE TABLE`
- `ALTER TABLE`
- `DROP TABLE`

DDL berbeda dengan DML yang digunakan untuk memanipulasi isi data. DDL lebih berfokus pada struktur dan aturan database.

---

### 2.2 Primary Key

Primary Key merupakan kunci utama yang digunakan sebagai identitas setiap baris dalam tabel. Nilai Primary Key harus unik dan tidak boleh `NULL`.

Pada database Kopma, Primary Key digunakan pada setiap tabel untuk membedakan satu data dengan data lainnya.

---

### 2.3 Foreign Key

Foreign Key merupakan kunci yang digunakan untuk menghubungkan satu tabel dengan tabel lainnya. Nilainya harus mengacu pada data yang tersedia pada tabel induk.

Foreign Key menjaga integritas referensial sehingga transaksi tidak dapat menggunakan petugas, anggota, barang, atau pemasok yang tidak tersedia.

---

### 2.4 UNIQUE

Constraint UNIQUE digunakan untuk memastikan bahwa suatu nilai tidak boleh sama dengan nilai pada baris lainnya.

Contohnya pada `kode_barang`, setiap barang harus mempunyai kode yang berbeda.

---

### 2.5 CHECK

CHECK digunakan untuk memberikan batasan terhadap nilai yang boleh dimasukkan.

Contohnya:

```sql
CHECK (qty_detail_penjualan > 0)
```

Dengan aturan tersebut, jumlah barang tidak boleh bernilai nol atau negatif.

---

### 2.6 NOT NULL

NOT NULL digunakan untuk memastikan sebuah kolom harus memiliki nilai. Contohnya `nama_barang` tidak boleh kosong karena setiap barang harus memiliki nama.

---

### 2.7 DEFAULT

DEFAULT digunakan untuk memberikan nilai otomatis apabila pengguna tidak memberikan nilai.

Contohnya stok barang dapat diberikan nilai awal `0`.

# BAB X  
## ANALISIS

### 10.1 Analisis Primary Key

Primary Key digunakan untuk memberikan identitas unik pada setiap data. Pengujian kode petugas `K01` menunjukkan bahwa ketika kode yang sama dimasukkan kembali, MariaDB menghasilkan error `1062`.

Dengan demikian, database berhasil mencegah data dengan identitas yang sama.

---

### 10.2 Analisis Foreign Key

Foreign Key digunakan untuk menjaga hubungan antar tabel. Pada pengujian, penggunaan petugas `XXX`, anggota `XXX`, dan barang `XXX` ditolak oleh MariaDB dengan error `1452`.

Hal tersebut menunjukkan bahwa data pada tabel anak tidak dapat dibuat apabila data induknya tidak tersedia.

---

### 10.3 Analisis CHECK

CHECK digunakan untuk memastikan nilai memenuhi aturan tertentu. Pada tabel `detail_penjualan` dan `detail_pembelian`, jumlah barang harus lebih besar dari nol.

Ketika nilai `0` digunakan, muncul error `4025`. Dengan demikian aturan jumlah barang berhasil dijaga oleh server.

---

### 10.4 Pemetaan Kode Error

| Kode | Constraint | Penyebab |
|---|---|---|
| 1062 | PRIMARY KEY / UNIQUE | Data duplikat |
| 1452 | FOREIGN KEY | Data induk tidak tersedia |
| 4025 | CHECK | Nilai tidak memenuhi kondisi CHECK |

---

### 10.5 Analisis Urutan Penghapusan Tabel

Tabel detail merupakan tabel anak yang memiliki Foreign Key menuju tabel transaksi. Oleh karena itu, tabel detail harus dihapus terlebih dahulu.

Jika tabel induk dihapus ketika masih digunakan oleh tabel anak, MariaDB dapat menghasilkan error `1451`.

Urutan penghapusan yang aman adalah:

```text
detail_pembelian
detail_penjualan
pembelian
penjualan
pemasok
barang
anggota
petugas
```

---

### 10.6 Analisis ON DELETE CASCADE

Pada hubungan `penjualan` dengan `detail_penjualan`, penggunaan `ON DELETE CASCADE` memungkinkan detail transaksi ikut terhapus ketika kepala transaksi dihapus.

Hal ini sesuai untuk data detail yang keberadaannya bergantung pada transaksi induknya.

Sebaliknya, data barang tidak seharusnya otomatis terhapus bersama detail transaksi karena barang merupakan data master yang dapat digunakan pada transaksi lain.

---

### 10.7 Analisis ALTER TABLE

Perintah `ALTER TABLE` memungkinkan struktur tabel diubah tanpa harus membuat tabel baru. Pada praktikum ini kolom `tgl_kedaluwarsa` berhasil ditambahkan dan kemudian dihapus kembali.

Penggunaan ALTER TABLE sangat berguna ketika terdapat perubahan kebutuhan sistem.
