# BAB I  
## PENDAHULUAN

### 1.1 Latar Belakang

Basis data merupakan salah satu komponen penting dalam pembangunan sistem informasi. Data yang disimpan dalam basis data harus memiliki struktur yang jelas serta aturan yang dapat menjaga konsistensi dan keamanannya. Oleh karena itu, selain membuat tabel, diperlukan aturan atau constraint yang dapat mencegah masuknya data yang tidak sesuai dengan kebutuhan sistem.

Pada praktikum Modul 5 dilakukan pembangunan struktur basis data Kopma menggunakan Data Definition Language (DDL) pada MariaDB. Rancangan database yang telah diperoleh dari proses normalisasi dan ERD kemudian diterapkan menjadi tabel-tabel yang dapat digunakan oleh sistem.

Dalam praktikum ini diterapkan beberapa constraint, yaitu PRIMARY KEY, FOREIGN KEY, UNIQUE, NOT NULL, DEFAULT, dan CHECK. Constraint tersebut digunakan untuk menjaga integritas data dan menerapkan aturan bisnis secara langsung pada database.

Selain membuat tabel, dilakukan pula pengujian dengan memasukkan data yang sengaja melanggar constraint. Pengujian tersebut menghasilkan beberapa error, seperti error 1062 karena data duplikat, error 1452 karena Foreign Key tidak memiliki data induk, dan error 4025 karena nilai tidak memenuhi aturan CHECK.

Praktikum juga mencakup perubahan struktur tabel menggunakan ALTER TABLE, pemeriksaan struktur dengan SHOW CREATE TABLE, pemeriksaan seluruh tabel menggunakan SHOW TABLES, serta perbandingan struktur fisik database dengan ERD melalui phpMyAdmin Designer.

---

### 1.2 Tujuan Praktikum

Tujuan dari praktikum Modul 5 adalah:

1. Menerjemahkan skema relasional 3NF menjadi perintah CREATE TABLE.
2. Menentukan tipe data yang sesuai untuk setiap atribut.
3. Menerapkan PRIMARY KEY pada setiap tabel.
4. Menerapkan FOREIGN KEY pada setiap relasi.
5. Menerapkan UNIQUE untuk mencegah data yang sama.
6. Menerapkan NOT NULL dan DEFAULT sesuai kebutuhan.
7. Menerapkan CHECK untuk menjaga aturan nilai data.
8. Menggunakan ALTER TABLE untuk mengubah struktur tabel.
9. Menguji constraint dengan data yang melanggar aturan.
10. Membandingkan database fisik dengan ERD menggunakan phpMyAdmin Designer.
11. Menyimpan dan mengunggah file DDL menggunakan Git dan GitHub.

# BAB II  
## DASAR TEORI

### 2.1 Data Definition Language (DDL)

Data Definition Language atau DDL merupakan bagian dari SQL yang digunakan untuk membuat, mengubah, dan menghapus struktur database.

Perintah DDL yang digunakan pada praktikum antara lain:

- `CREATE TABLE`
- `ALTER TABLE`
- `DROP TABLE`

DDL digunakan untuk membangun struktur tabel sebelum tabel tersebut diisi dengan data.

---

### 2.2 Tipe Data

Pemilihan tipe data harus disesuaikan dengan jenis data yang akan disimpan. Pemilihan tipe data yang tepat dapat menghemat ruang penyimpanan dan mencegah data yang tidak sesuai.

Beberapa tipe data yang digunakan pada rancangan Kopma antara lain:

| Tipe Data | Penggunaan |
|---|---|
| `CHAR` | Kode dengan panjang tetap |
| `VARCHAR` | Data teks dengan panjang bervariasi |
| `INT` | Bilangan bulat |
| `SMALLINT` | Bilangan bulat dengan rentang lebih kecil |
| `DECIMAL(12,2)` | Nilai uang |
| `DATE` | Tanggal |
| `DATETIME` | Tanggal dan waktu |
| `ENUM` | Data dengan pilihan nilai tertentu |

---

### 2.3 PRIMARY KEY

PRIMARY KEY digunakan sebagai identitas unik setiap baris dalam tabel. Nilai PRIMARY KEY tidak boleh sama dan tidak boleh NULL.

---

### 2.4 FOREIGN KEY

FOREIGN KEY digunakan untuk menghubungkan tabel anak dengan tabel induk. Nilai pada kolom Foreign Key harus mengacu pada data yang tersedia di tabel induk.

---

### 2.5 UNIQUE

UNIQUE digunakan untuk memastikan suatu nilai tidak boleh memiliki duplikat.

---

### 2.6 NOT NULL

NOT NULL digunakan untuk memastikan sebuah kolom wajib memiliki nilai.

---

### 2.7 DEFAULT

DEFAULT memberikan nilai otomatis apabila nilai untuk suatu kolom tidak diberikan.

---

### 2.8 CHECK

CHECK digunakan untuk memastikan nilai yang dimasukkan memenuhi kondisi tertentu.

Contohnya:

```sql
CHECK (qty_detail_penjualan > 0)
```

Artinya jumlah barang yang dijual harus lebih besar dari nol.

# BAB XI  
## ANALISIS

### 11.1 Analisis Error 1062

Error `1062` terjadi ketika memasukkan data dengan nilai yang sudah digunakan sebagai Primary Key atau UNIQUE.

Pada pengujian, kode petugas `K01` dimasukkan kembali sehingga MariaDB menolaknya.

Hal tersebut membuktikan bahwa constraint Primary Key berhasil menjaga keunikan data.

---

### 11.2 Analisis Error 1452

Error `1452` terjadi ketika data yang dimasukkan pada Foreign Key tidak memiliki pasangan pada tabel induk.

Contohnya penggunaan kode petugas `XXX`, nomor anggota `XXX`, atau kode barang `XXX`.

Dengan adanya Foreign Key, database tidak membiarkan transaksi memiliki referensi ke data yang tidak tersedia.

---

### 11.3 Analisis Error 4025

Error `4025` muncul karena nilai yang dimasukkan tidak memenuhi kondisi CHECK.

Pada `detail_penjualan` dan `detail_pembelian`, nilai quantity `0` ditolak karena aturan:

```sql
CHECK (qty > 0)
```

Aturan tersebut menjaga agar jumlah barang dalam transaksi tidak bernilai nol atau negatif.

---

### 11.4 Hubungan Constraint dengan Aturan Bisnis

| Constraint | Fungsi | Aturan yang dijaga |
|---|---|---|
| PRIMARY KEY | Identitas unik | Mencegah identitas ganda |
| UNIQUE | Nilai harus unik | Mencegah kode duplikat |
| FOREIGN KEY | Menjaga relasi | Referensi induk harus tersedia |
| NOT NULL | Nilai wajib ada | Data penting tidak boleh kosong |
| DEFAULT | Nilai awal otomatis | Mempermudah pengisian data |
| CHECK | Membatasi nilai | Quantity harus > 0 dan stok tidak negatif |

---

### 11.5 Analisis ON DELETE CASCADE

`ON DELETE CASCADE` digunakan pada hubungan kepala transaksi dengan detail transaksi.

Apabila suatu transaksi dihapus, detail transaksi yang bergantung pada transaksi tersebut juga dapat dihapus.

Namun, pada tabel barang tidak digunakan CASCADE untuk menghapus barang secara otomatis karena barang merupakan data master. Data barang dapat digunakan pada banyak transaksi sehingga penghapusan barang dapat menyebabkan hilangnya referensi dan mengganggu riwayat transaksi.

---

### 11.6 Analisis Urutan DROP TABLE

Tabel anak harus dihapus sebelum tabel induk karena Foreign Key masih mengacu pada tabel induk.

Urutan penghapusan yang benar adalah:

```text
detail_pembelian
detail_penjualan
pembelian
penjualan
pemasok
barang
anggota
petugas
```

Jika tabel induk dihapus terlebih dahulu ketika masih memiliki tabel anak yang merujuk kepadanya, MariaDB dapat memberikan error `1451`.

# BAB XII  
## LATIHAN DAN MODIFIKASI

### 12.1 CHECK Stok Minimum

Aturan tambahan yang diminta adalah memastikan `stok_min_barang` tidak boleh negatif.

Constraint dapat ditambahkan menggunakan:

```sql
ALTER TABLE barang
ADD CONSTRAINT ck_barang_stok_min
CHECK (stok_min_barang >= 0);
```

Pengujian dapat dilakukan dengan mencoba memberikan nilai negatif.

```sql
UPDATE barang
SET stok_min_barang = -1
WHERE kode_barang = 'B001';
```

Perintah tersebut seharusnya ditolak oleh MariaDB karena melanggar constraint CHECK.

### 12.2 ON DELETE SET NULL

Foreign Key anggota pada tabel penjualan dapat diubah agar ketika data anggota dihapus, nilai `id_anggota` pada penjualan menjadi NULL.

Konsepnya menggunakan:

```sql
ON DELETE SET NULL
```

Penggunaan SET NULL sesuai dengan konsep bahwa pembeli umum dapat memiliki `id_anggota` NULL. Namun penerapannya harus mempertimbangkan kebutuhan penyimpanan riwayat transaksi dan kebijakan perlindungan data pribadi.
